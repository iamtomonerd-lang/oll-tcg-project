# 測定：紫／血醒 22枚を実装してみた結果

「効果をデータで書くようにしたら本当に安くなったのか」を、7枚ではなく22枚で測った記録。
測定日：2026-07-30。対象は紫・系統「血醒」の22枚（それまで実装していた赤・風牙とは別系統）。

## 結論（先に数字）

| 項目 | 結果 |
|---|---|
| 書けたカード | 18枚 / 22枚（82%） |
| 書けなかったカード | 4枚（10・16・21・22） |
| 新しく必要になった語彙 | 4個 |
| かかった時間（語彙の追加） | 約4分 |
| かかった時間（18枚のデータ化） | 約3分 |
| かかった時間（動作確認とバグ修正） | 約9分 |
| 合計 | 約16分 |
| 1枚あたり | 約50秒 |

比較のため、以前の「1枚1クラス」だった頃の実測は **1枚あたり614行・数時間** だった。
データで書く形式では **1枚あたり10〜25行** に収まっている。

ただし「1枚50秒」を額面どおり受け取ってはいけない。理由は下の「注意」に書く。

## 語彙の飽和は起きているか

22枚を分解して、新しく実装が必要だった語彙は次の4個だけだった。

1. `破壊時` トリガー（カード1・2）
2. `残す` … 「コアがN個になるように置く」（カード12・15・19）
3. `消滅した` 条件 … 「消滅したなら」（カード20）
4. `直前成功` 条件 … 「そうしたなら」（カード13）

一方、**新しい語彙が要らなかったもの**：

- 「それの{ソウルコア}以外のコア1個をリザーブに置く」→ 既存の `コア移動` の `除外: 'ソウルコア'` でそのまま書けた。22枚のうち8枚がこの形。
- 【起動：メイン】→ `タイミング: 'メイン'` を書くだけ。仕組みは既にあった。
- 「ボイドからコア1個を自分のリザーブに置く」→ `コア移動` の移動元にボイドを指定するだけ（ボイドが無尽蔵である扱いだけ1箇所足した）。
- 《真界放》『アタック中』のBP増加 → 赤のカードと同じ書き方で通った。

**別の色・別の系統に移っても、必要な新語彙は4個で済んだ。** これは語彙が飽和に近づいている証拠と言える。
22枚のうち後半12枚（11〜22）で新しく要ったのは3個、最後の2枚（21・22）は
「新語彙が1個要る」ではなく「そもそも設計にない種類の効果」だった（後述）。

## 書けなかった4枚と、その理由

### カード16・22 … インタプリタが持っていない“種類”の効果

- **16**：「このターン中、自分のライフはコア1個の相手のスピリットのアタックでは減らない」
- **22**：「このスピリットはコスト4以下の相手のスピリットからブロックされない」

これは「何かをする」効果ではなく **「ルールを書き換える」効果** である。
今のインタプリタは「処理を順に実行する」ものなので、
「アタックの解決のしかたを変える」「ブロックできる条件を変える」は表現できない。

これは語彙を1個足せば済む話ではなく、**継続的な制約を宣言し、
ルール処理側がそれを参照する仕組み**（常在効果の登録簿）が必要になる。
バトスピには『このスピリットは〜されない』系のカードが大量にあるので、
ここは早めに作るべき土台だと考えている。

### カード10 … 3つの別々の要素が同時に必要

「自分が系統：「血醒」を持つスピリットカードを召喚する時、このターンに相手のスピリットが
消滅していたなら、このネクサスに紫シンボル1つを追加する。」

- 「召喚する時」＝召喚されたカードを条件で絞るトリガー（今は自分の召喚しか見ていない）
- 「このターンに〜消滅していた」＝ターン内の履歴の記録
- 「シンボルを追加する」＝シンボルを書き換える手段

3つとも今は無い。1枚のために3個作るのは割に合わないので後回しにした。

### カード21 … コアの「合計」配分

「相手のスピリット1体を指定する。それのコア合計2個をリザーブに置く。…かわりに指定する体数を2体までにする。」

「体数を2体までにする」だけなら既にある仕組み（変数）で書ける。
書けないのは **「合計2個」を複数の対象に配る** ところ。
今の `コア移動` は「対象1体ごとにN個」しか表せない。
「合計N個を対象間で分ける」には、配分をプレイヤーに決めさせる仕組みが必要になる。

### カード17 … これはカードの不足ではない

「《ソウルマジック：紫》自分の紫シンボルがあれば{ソウルコア}だけで使用できる。」

これは効果ではなくコストの払い方を変えるキーワードなので、
キーワードだけ書いて効果は空にした。効果本体のテキストが未提供のため、そこは書いていない。

## 実装していない判断：「置くコアは相手が選ぶ」

22枚中5枚（12・15・18・19・21）に「（置くコアは相手が選ぶ）」がある。
これは **相手側に判断を求める** 指示で、今の仕組みは
「効果を使った本人が選択に答える」前提になっている。

現状は「通常コアから先に置く（＝ソウルコアが残りやすい）」という決め方で動かしている。
コアはソウルコア以外は区別が無いので、多くの場面では結果が変わらない。
ただしソウルコアを残すかどうかで結果が変わる場面はあり、そこは正しくない。

副作用として、カード18「コア2個をリザーブに置く」は、相手の通常コアが1個しか無いときに
1個も置けない（本来は相手がソウルコアを置く選択もできる）。

## 測定の途中で見つかった、既にあったバグ

数を稼ぐより大事だったのはこれ。**カードを22枚並べたことで初めて出た** 不具合が3つある。

### 1. 「コアをリザーブに置く」が見た目だけの処理だった

効果でコアを剥がしても、**Lvが下がらず、コアが0になっても消滅しなかった**。
効果からのコア移動が、Lvの再計算とルール処理（消滅判定）を通っていなかった。

紫のカードは22枚中10枚がコアを剥がす効果なので、この系統を実装するまで気づけなかった。
赤のカード7枚では一度も踏まなかった経路だった。

### 2. BP比べで破壊されたスピリットの『破壊時』が発揮されなかった

バトルで負けた側は「待機状態にする → トラッシュへ置く」が一続きで実行されていて、
その間に効果を挟む窓が無かった。『破壊時』効果を持つカードを作って初めて分かった。

### 3. 払えないコストの【起動】効果が候補に出続けていた

「このネクサスを疲労させる▶…」の効果が、既に疲労していても候補に出ていた。
撃っても何も起きない手が永久に残るため、自動対戦が終わらなくなった。
「待機状態のカードが効果を撃てる」状態にもなっていた。

いずれも直してテストを付けた。3つとも **修正を外すとテストが落ちること** を確認済み。

## どうやって「動いた」と確認したか

型が通るだけでは何の証拠にもならないので、3段階で確かめた。

1. **18枚すべてを、対象が揃った盤面で実行**（`紫血醒カード群.test.ts`）
   「対象がいません」「コアを動かせませんでした」等のログが出たら失敗とする。
   → `残す` の計算を意図的に壊すと4件落ちることを確認（テストが素通りしていない証拠）。
2. **新しい語彙の個別確認**：成立する場合と成立しない場合の両方を書いた
   （消滅したときだけドローする／破壊できたときだけコアを置く）。
3. **紫デッキ30枚で自動対戦**（`ウェブサーバー.test.ts`）
   6回すべて決着し、召喚・配置・使用・アタック・選択のすべてを通ることを確認。

さらにAI同士で8試合回して、効果が実際に何回働いたかを数えた。

```
誘発した事象: 召喚時 24回 / アタック時 44回 / 破壊時 8回
実際に起きたこと: コア移動 17回 / ドロー 10回
```

## 注意：「1枚50秒」を信用しすぎないこと

正直に書く。この数字には次の下駄が履かせてある。

- **カード名・コスト・BP・シンボルが未提供**だったので仮の値を入れた。
  実物を入力するなら1枚あたり1〜2分は別にかかる。
- **書きやすい18枚を選んで測っている**。難しい4枚を含めれば平均は上がる。
- **22枚のうち効果の形が重複している**（コアを1個剥がす形が8枚）。
  同じ形が並ぶと2枚目以降はほぼコピーなので、1枚あたりが実際より安く見える。
- **動作確認とバグ修正に9分**かかっている。これは枚数に比例しないが、
  新しい系統に手を出すたびに発生すると考えたほうがいい。

それでも、**以前の「1枚で数時間」からは桁が変わっている**とは言える。
500枚を目安にすると、テキストが既存語彙で書ける範囲なら
「1枚あたり1〜2分＋新語彙の実装」という見積りになる。

## 次にやるべきこと（優先順）

1. **常在効果の登録簿を作る**（カード16・22の種類）
   「〜されない」「〜できない」はバトスピの主要な効果群で、今はまったく表現できない。
   1枚のための追加ではなく、土台が1つ足りていない。
2. **相手に判断を求める仕組み**（「置くコアは相手が選ぶ」、22枚中5枚）
   選択の中断・再開は既にあるので、答える人を切り替えられるようにするだけで済むはず。
3. **ターン内の履歴**（「このターンに〜が消滅していた」）
   カード10だけでなく紫のデッキ全体で参照される条件。
