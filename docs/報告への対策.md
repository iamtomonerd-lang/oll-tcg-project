# 実機の報告に、何を原因と見て、どう直したか

1枚ずつの確認で挙がった **失敗6件・検証不能3件・機能不備6件** に対する記録。

**「直した」と書いてあるものは、直しを外すと検査が落ちることまで確かめてある。**
落ちない検査は、何も守っていない。

---

## いちばん大事な訂正

**ライフが減ったコアは【リザーブ】に置かれる。トラッシュではない。**

前回わたしは「トラッシュが正しい」と考えて `バトル管理.ライフダメージを与える` を
書き換えたが、これは誤りだった。差し戻してある。

この訂正で、コアの流れは次の通りに確定した。

```
ライフが減る      → リザーブ
コストを支払う    → トラッシュ
リフレッシュステップ → トラッシュのコアがすべてリザーブへ戻る
```

つまり **トラッシュにコアが入る道はコストの支払いだけ**で、
「自分のトラッシュのコアを置く」効果（キュペル・飛赫レンシス・最奥：風牙岩Lv2・
ブレイククロー）は、**そのターンに自分が払ったコアを拾い直す**効果ということになる。

## 失敗と報告されたもの

### 1. グライファーLv1・最奥：風牙岩Lv1 ── 起動効果を拒否できない

**原因は効果ではなく、パネルの重なりだった。**

`#activatePanel` に閉じるボタンが無く、CSSが `left:16px; top:50%; transform:none`。
DOM順で `#flashPanel` の**後**にあり z-index も同じなので、
画面が狭いと割り込みパネルの「何もしない」を上から覆っていた。

**直し**

- 割り込みの窓が開いている間は、起動効果を**割り込みパネルの中**に並べる（パネルは常に1枚）
- メインステップ用のパネルには「使わない」を足した
- `top`/`transform` を直し、`max-height` と `overflow-y` を付けて画面外へ伸びないようにした

**確かめ方**（`scratchpad/画面確認2.mjs`、iPad相当の 820×1180）

起動直後から利用者が押せるものだけを辿り、窓が開くたびに
`document.elementFromPoint` で「何もしない」が本当に押せるかを見る。

| | 窓を見た回数 | 別パネルが重なった | 「何もしない」が覆われた |
|---|---|---|---|
| 直す前 | 20 | **12回** | **12回** |
| 直した後 | 20 | 0回 | 0回 |

覆っていたのは `effect-target-btn` ＝起動効果のボタンそのものだった。

### 2. セルタリウス・飛赫レンシス ── 《継召》ができない

**判定も管理も実装済みだったが、呼ぶ者が誰もいなかった。**
`継召管理.発揮する` の呼び出し箇所は **0件**。
`ゲームAPI` の 召喚／配置／使用 は `継召による軽減数` に既定の0を渡し続けていた。

**直し**

```
支払い画面
  → /api/action/summon|place|use の 支払い.継召除外（トラッシュのカード識別子）
  → 試合.継召を発揮する
  → 継召管理.発揮する（戻り値＝満たした軽減シンボル数）
  → 召喚する／配置する／使用する の 継召による軽減数
```

除外は**コアを1個も動かす前**に確かめる。先に食べてしまうと、
支払いに失敗したときトラッシュのカードだけが消えて戻ってこない。

**テスト** `管理/キーワードの支払い.test.ts`
除外した枚数だけコストが軽くなること／EXシンボルを持たないカードは食べられないこと／
軽減シンボルの枠を超えた指定はまるごと無効（1枚も除外されない）こと。

### 3. フレイムハリケーン ── 《ソウルマジック》が発動しない

同じ形。`ソウルマジック管理` は `試合` が生成するだけで、**使用箇所0件**だった。

**直し** `使用管理.使用する` に「ソウルコアだけで払う」経路を足し、
`ソウルマジック判定.発揮可能か`（該当色のシンボルが自分の場にあるか＋ソウルコアがあるか）で許可する。
該当色はカードの属性から取る。支払い画面のチェックから選ぶ。

**テスト** 同上。コスト6を払わずソウルコア1個だけが減ること／
場に赤のシンボルが無ければ使えず、ソウルコアも動かずマジックも手札に残ること。

---

### 4. ブレイククロー［メイン］・最奥：風牙岩Lv2 ── トラッシュのコア回収が働かない

**エンジンは正しく動いていた。** 再現テストを先に書いて切り分けた
（`カードデータ/トラッシュのコア回収.test.ts`）。

- コストを払うと、その数だけコアがトラッシュに積まれる ✔
- ブレイククロー［メイン］は、**疲労した赤の味方がいれば**トラッシュのコアが1個リザーブに戻る ✔
- 疲労した味方がいなければ何も起きない（これは正しい）
- 最奥：風牙岩Lv2は、**トラッシュに通常コアがあれば**選んだスピリットに1個置く ✔
- トラッシュが空なら、選ぶ画面は出るが何も起きない（これも正しい）

つまり実機で見えていたのは、**条件を満たしていなかった**か
**トラッシュが空だった**かのどちらか。第1メインステップでは誰も疲労していないので、
ブレイククローの条件は成立しない。

**では何が問題だったか ── 何も起きなかった理由が画面に出ないこと。**

**直し**

- `効果実行器` が直近のログを溜め、`状態.効果ログ` として画面に届ける
- 画面は、まだ見せていない行をトーストで出す
- トラッシュのコア数を盤面に出す（撃ちどきが分かる）
- 支払い画面からソウルコアを狙ってトラッシュへ送れるようにした
  （キュペルLv2の「トラッシュの{ソウルコア}を置く」はこれが無いと試せない）

### 5. ブレイククロー／オフェリングドロー／フレイムハリケーンの［フラッシュ］

前回の修正で入っている（画面が手札の押せる条件を「メインステップ中」だけで見ていた）。
APIは元から窓の中での使用を許していたので、画面だけの穴だった。

なお **［フラッシュ］のマジックは自分のメインステップでも使える**（今の実装のまま）。

## 検証不能と報告されたもの

### 6. キュペルLv1/Lv2・飛赫レンシスLv2 ── トラッシュにコアを置けない

支払い元がリザーブ決め打ちで、しかも「通常コア優先」で固定だったため、
**狙ってコアをトラッシュへ送る手段が無かった**。とくにソウルコアは、
通常コアが1個でも余っていれば絶対にトラッシュへ行かなかった。

**直し** ── 下の 7・8 と同じ仕組みで解消。支払い画面から
「リザーブ／どのカードの上／通常かソウルか」を1個ずつ指定できる。

### 支払い画面はいつ出るか

**ふだんは出ない。** 利用者の指定どおり「ふだんは自動、必要なときだけ画面」。

- リザーブだけでは払えない（カードの上のコアが要る）
- 《継召》が使える
- 《ソウルマジック》が使える

このいずれかのときだけ開く。押せるかどうか（`支払可能`）の意味は元のまま
**「リザーブだけで払えるか」**にしてある。ここを広げたら、自動払いの道と食い違って
「押せるのに拒否される」が起きた（テスト5本が落ちて気づいた）。

## ついでに入れたもの

**`?seed=11` を付けて開くと、同じ引きの試合を何度でも作れる。**

画面の不具合を「直す前」「直した後」で比べるには同じ試合である必要があり、
これが無いと毎回別の試合になって比較にならない。実際に一度それで
「直しを外しても検査が通る」という誤った結論を出しかけた。
