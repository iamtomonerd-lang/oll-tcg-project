# AIを強くする

「学習し、より高度な対戦ができるようにしたい」（利用者）に対する作り。

決めたこと（利用者の判断）：

| 決めごと | 選んだもの |
|---|---|
| 学習の形 | **両方** ＝ オフラインで鍛えて焼き込み＋手元で微調整 |
| 1手に待てる時間 | **1〜3秒**（先読みまで踏み込む） |
| 強さの見え方 | まずは最強のものだけ。**あとでレート戦**（1500を基準に正規分布） |

段階に分けて出す。**この文書は段4が終わった時点のもの。**

| 段 | 中身 | 状態 |
|---|---|---|
| 1 | 手を広げる＋評価関数で選ぶ＋強さのつまみ | **済** |
| 2 | 盤面の複製（先読みの土台） | **済** |
| 3 | 先読み（打ってみて測る） | **済**（1手先。まだ深く読む余地が大きい） |
| 4 | 学習（自己対戦で重みを鍛えて焼き込む） | **済** |
| 5 | 手元での微調整＋レート戦 | これから |

いまの強さ … 練習用AIに対して **87.3%**（段1は76.0%）

---

## 段1でやったこと

### まず「手が届く範囲」を広げた

いちばん効いたのはここ。賢さ以前に、**AIは手札の半分を使えていなかった**。

| これまでの練習用AI | いまの思考AI |
|---|---|
| スピリットの召喚だけ | 召喚・**ネクサスの配置**・**マジックの使用** |
| — | **起動効果** |
| 割り込みでは常にパス | **［フラッシュ］のマジック・起動効果を撃つ** |
| — | 《ソウルマジック》での支払い |
| リザーブからのLvアップ | 同じ |

`AI/打てる手.ts` が「いま何ができるか」を全部並べる。
挙げる側（打てる手）と選ぶ側（思考AI）を分けてあるので、
**選び方だけを学習で差し替えられる。**

### 盤面を1つの数字にした

`AI/盤面評価.ts`。ライフ・シンボル数・BP・手札・コアの置き場所などに重みを掛けて足す。

**強さの正体はこの重み。** 思考AIの側には強さを持たせていない。
学習とはこの重みを自己対戦で調整することで、反映先が2か所に散らないようにしてある。

重みは `評価の重み` として外から差し替えられる。

### 強さのつまみを1本入れた

`強さ`（0〜1）＝**最善手を選ぶ確率**。レート戦を入れるとき、
レートからこの数値を作れば強さが連続的に動く。

はじめは「上から何番目までを候補にするか」で弱くしていたが、
手が数個しかない場面では 強さ0.6 でも上位2手に絞られ、最強とほとんど差が出なかった
（実測 77% → 75.5%）。確率にしたら素直に効くようになった。

## 測ったこと

`AI/腕試し.ts`。AI同士を何百試合も戦わせて勝率を出す。
**先攻・後攻を入れ替えて半分ずつ**戦わせる（入れ替えないと「強さ」ではなく「先攻」を測る）。
種を渡すので何度回しても同じ結果になる。

### 土俵が傾いていないこと

| 組み合わせ | 先の勝率 |
|---|---|
| 練習用AI 対 練習用AI | 49.0% |
| 思考AI 対 思考AI | 54.0% |

同じもの同士で五分。ここが崩れていたら、下の数字は強さではなく測り方を見ている。

### 強くなったか（200試合・先後入れ替え）

| 種 | 思考AI の勝率 |
|---|---|
| 1〜200 | **74.5%** |
| 501〜700 | **74.5%** |

### 強さのつまみ（300試合、対 練習用AI）

| 強さ | 勝率 |
|---|---|
| 1（最強） | 75.0% |
| 0.8 | 74.7% |
| 0.6 | 63.3% |
| 0.4 | 52.3% |
| 0.2 | 54.3% |
| 0 | 38.3% |

0.2 と 0.4 の逆転は誤差の範囲。両端はしっかり離れている。

### 実際の対戦の道（ゲームAPI）でも使っているか

自己対戦だけで測ると、画面に繋がっていなくても数字は出てしまう。
`/api/` を通した対戦でも数える。

| | 結果 |
|---|---|
| 12試合でAIがマジックを使った回数 | **56回**（直す前は 0回） |
| 割り込みの窓でAIに判断を尋ねた回数 | **90回**（直す前は尋ねてすらいなかった） |

画面（820×1180、起動直後から利用者が押せるものだけを辿る）。種 11/3/7/77/5：

- 5種すべてで**決着まで進む**（進行が詰まらない）
- AIは1試合あたり**5〜7枚のマジックを使う**
- 画面のエラーは0件

## 途中で分かったこと

### AIがマジックを一度も撃たなかった

手を挙げられるようにしただけでは撃たなかった。
見込みの計算が「手札が1枚減る・コアが減る」の引き算だけになっていて、
**撃つ手がいつも損に見えていた**（フレイムハリケーンで −10点）。

効果の値打ちを重みとして立てた（`マジックを撃つ値打ち` `召喚時効果が当たる値打ち`）。
これで撃つようになった。中身までは読んでいないので、
段2で盤面を複製できるようになったら実測に置き換える。

### ［フラッシュ］のマジックは取っておくべきか → 測ったら「変わらない」

「相手のアタックに合わせて撃つほうが得では」と考えて、
メインで撃つときの割引を入れて500試合ずつ測った。

| 割引 | 素の思考AIに対する勝率 |
|---|---|
| 0（割り引かない） | 51.8% |
| 20 | 49.0% |
| 40 | 49.4% |
| 60 | 49.4% |
| 80 | 49.4% |

**得にならなかった。** 重みは残したまま既定を0にしてある（学習で見直せる）。
思い込みで手を入れず、測ってから決めること。

## 段2以降でやること

### 段2：盤面の複製

いまは**打った手を戻せない**ので、手の良し悪しを「見込み」で足し引きしている。
効果が何をするかは読めていない。

複製できるようになれば「打ってみて測る」に置き換わり、
見込みのズレがまるごと消える。1〜3秒の先読みもここが土台になる。

データ層は小さい（`カード`・`ゾーン`・`プレイヤー` はどれも
`状態: Map` と `数値: Map` を持つ `ゲーム物`、合わせて472行）。
面倒なのは **管理クラスがカードの参照を持っている**ところで、
複製するときに参照先を張り替える必要がある。

| 参照を持つもの | 中身 |
|---|---|
| 一時効果管理 | BP変更記録 |
| 常在効果管理 | 登録済み制約 |
| 誘発型効果管理 | 誘発予約のキュー |
| 効果実行器 | 選択待ちの対象候補 |

### 段4：学習

自己対戦は **1試合1.76ms**（200試合で352ms）。
数万〜数十万試合を回して重みを鍛えるのは十分に現実的。

鍛えた重みは `学習した重み.ts` に書き出してビルドに含める。
ブラウザ側はサーバー無しのまま、開いた瞬間から鍛えた強さになる。

### 段5：レート戦

`強さ`（0〜1）が既に1本通してある。レート1500を基準に正規分布で振り、
そこから 強さ を作れば、そのまま繋がる。

## 引っかかったところ（同じ轍を踏まないために）

### 画面の確認で「ボタンの hidden」を見てはいけない

パネルが閉じていても、**中のボタンの `hidden` は false のまま**。
大きさが 0×0 になるだけ。

これで2回はまった。1回目は「ブロックしない」を800回押し続けて対戦が進まず、
2回目は閉じたはずの効果パネルのボタンを755回押していた。
どちらも**アプリは正しく、確かめ方が間違っていた**。

`position: fixed` で `offsetParent` が使えないのと同じ話で、
**見えているかは `getBoundingClientRect()` の幅・高さで見る。**
親のパネルの `hidden` も一緒に見ること。

### 種を1つに決め打ちしたテストは、AIを変えると落ちる

「［フラッシュ］のマジックをメインステップで撃つ」テストが、
AIを強くしたら落ちた。種11でその場面に入れなくなったため。

確かめたいのは「**その場面が来たら撃てること**」なので、
場面が現れるまで種を変えて探す形に直した。
AIの気分で落ちるテストは、直しても意味が伝わらない。

# 段2・段3：盤面を複製して、打ってみて測る

## 何が変わったか

段1のAIは「その手を打ったらどうなるか」を**見込みで足し引き**していた。
盤面を複製できなかったので、打った手を戻せなかったため。
効果が何をするかは読めず、下駄（重み）で表すしかなかった。

いまは **複製の上で実際に打って、出来上がった盤面を評価する**。
効果の結果まで盤面に出るので、下駄がいらない。

```
段1  この手を打つと 手札-1・コア-4 …… だいたい -45点くらいか
段3  複製して打ってみたら 相手のスピリットが1体消えた …… +31点
```

## 複製の作り

`試合.複製する(種)`。データ層と、状態を持つ管理を全部写す。

| 写すもの | 中身 |
|---|---|
| ゲームエンジン | プレイヤー・ゾーン・カード（**コアはゾーンとカードの中にある**ので一緒に付いてくる） |
| 一時効果管理 | 期限付きのBP補正 |
| 常在効果管理 | 期限付きの制約（「ブロックされない」など） |
| ターン履歴管理 | 『このターンにライフが減っていたなら』 |
| 誘発型効果管理 | 誘発の待ち行列 |
| 置換型効果管理 | 置換済みの事象 |
| 制限効果管理 | 〔ターン1回〕をもう使ったか |
| 効果実行器 | 片付け待ちのマジック・事象連番 |

カードを指している記録は、**複製したカードに差し替える**。
ここを怠ると、複製の中の記録が本物のカードを指したままになり、
複製をいじったつもりが本物に漏れる。

**効果の答え待ちの最中は複製を断る**（例外を投げる）。
途中で複製すると「誰に何を聞いていたか」を取り違えるため。
AIが手を選ぶのは常に答え待ちでない場面なので、これで足りる。

速さは **1回 0.054〜0.070ms**（毎秒 約15,000〜18,000回）。

## 測ったこと

### 複製が本物と同じか

`盤面の指紋` で盤面を1本の文字列にして比べる。

1. 複製した直後は本物と寸分たがわない
2. 複製に手を打っても本物は動かない
3. 本物と複製に同じ手を打てば、同じ盤面になる

### 強くなったか（300試合・先後入れ替え）

| | 練習用AI に対する勝率 |
|---|---|
| 見込みで選ぶ（段1） | 79.7% |
| **複製して打ってみる（段3）** | **84.3%** |

直接対決（先読み 対 見込み）… **57.7%**

### 利用者が待たされる時間

`/api/` を通した373手の実測。

| 中央値 | 95%点 | 最大 |
|---|---|---|
| **2ms** | 4ms | 17ms |

**許された1〜3秒に対して桁違いに余っている。**
いまは「自分の1手だけ」を読んでいるので、相手の返しまで読む・
手の順番を組み合わせて読む、といった深さを足す余地が大きい。

## 段2・段3で見つけた不具合

### テストが「空っぽ」を見ていた（複製の確認が素通りだった）

複製のテストを書いて通ったあと、念のため
**写しの呼び出しを1行ずつ消して、テストが落ちるか**を確かめた。

結果、**7つ全部を消してもテストは通った。**

途中まで進めただけの盤面では、どの管理も中身が空だったため。
空のものを写しても写さなくても同じで、あれは
「複製できている」ではなく「何も入っていない」を見ていた。

いまは中身を入れてから複製し、届いたかを1つずつ見ている。
7つのうちどれを消してもテストが落ちる。

**「テストが通った」と「テストが働いている」は別物。**
新しく守りを入れたら、**守りを外して落ちること**まで確かめる。

### コアの代金を二重に取っていた

先読みを入れたら、AIが**マジックを1枚も撃たなくなった**（40回 → 0回）。

調べると、複製の上では正しく相手を壊せていた。原因は評価の重みで、
`自分のトラッシュのコア: -2` が**同じ代金を二重に取っていた**。

```
コアを1個払う → リザーブから減る（-4）→ さらにトラッシュで罰（-2）＝ 1個6の値段
```

そのせいでコストの重い手が軒並み損に見えていた。
払った痛みは「リザーブから消えたこと」で既に表せている。

0 に直して、800試合×3つの種の範囲で測った。

| 種の範囲 | 同じ重み（ものさし） | トラッシュの罰なし |
|---|---|---|
| 1〜 | 51.7% | **58.6%** |
| 2001〜 | 50.2% | **56.5%** |
| 5001〜 | 47.3% | **54.6%** |

どの範囲でも約7ポイント上がった。練習用AIに対する勝率も 77.0% → **84.3%**。

**同じ重みどうしを「ものさし」として一緒に測ること。**
最初に測ったとき、ものさしを取らずに 53.2% を見て
「差がある」と読みかけた。ものさしを取ったら 50% 前後で、
53.2% はただのばらつきだった。

### 破壊は2段階（複製でも同じ）

複製の上で手を打ったあと、`効果実行器.キューを進める()` と
`ルール処理を実行する()` を呼ばないと、壊した相手が**待機状態のまま場に残る**。
評価がそれを生きていると数えるので、除去の手が全部損に見える。

盤面評価の側でも、**待機状態のカードは数えない**ようにした。
どちらか一方だけだと、また同じ形で間違える。

# 段4：学習（自己対戦で重みを鍛える）

## やり方

`AI/学習.ts`。山登り（(1+λ)進化戦略）。

```
1. いまいちばん強い重み＝王者 を持つ
2. 王者に少しずつ乱れを足した挑戦者を6人つくる
3. 王者と挑戦者を300試合ずつ戦わせ、はっきり勝ち越した者がいれば王者を交代
4. 当たりが出れば乱れを大きく、出なければ小さくして探し方を変える
```

**思考AI（判断の骨組み）には一切手を入れない。** 動かすのは重みだけ。
強さの反映先が2か所に散らないようにするため。

乱れの幅は**その項目自身の大きさに比例**させる。
BPは0.001台、ライフは100台と桁が違うので、同じ幅で動かすと小さい項目だけが吹き飛ぶ。

世代ごとに**違う種の範囲**で測る。同じ試合を見続けると、
「強い重み」ではなく「その試合に噛み合う重み」が育つ。

## 回し方

```bash
npm run 学習          # 20世代
npm run 学習 -- 40    # 世代数を指定
```

結果は `AI/学習した重み.ts` に書き出され、**ビルドに含まれる**。
ブラウザ側は何も変えなくてよく、開いた瞬間から鍛えた強さになる（サーバーは要らないまま）。

40世代でおよそ9分（1世代 約13.5秒）。

## 測ったこと

**すべて学習に使っていない種**で測り直している。
学習に使った種で測ると、その試合に噛み合っただけでも「強くなった」と出てしまう。

### 積み上がり（600試合・先攻後攻を入れ替えて半分ずつ、対 練習用AI）

| | 勝率 |
|---|---|
| 手で置いた重み＋見込み（段1） | 76.0% |
| 手で置いた重み＋先読み（段3） | 79.7% |
| **鍛えた重み＋先読み（段4）** | **87.3%** |

### 鍛えた重み 対 手で置いた重み（どちらも先読み）

| | 勝率 |
|---|---|
| 600試合 | **61.3%** |
| 1000試合（学習の最後の自動確認） | **62.0%** |
| ものさし：同じ重みどうし | 52.5% |

### 待たされる時間

中央値 **2ms**・95%点 4ms・最大 8ms。段3と変わらない
（学習は重みを変えるだけで、考える量は増えないため）。

## 鍛えた結果、何が変わったか

| 項目 | 手で置いた値 | 鍛えた値 | 読み取れること |
|---|---|---|---|
| 自分のシンボル数 | 22 | **36.9** | 打点をずっと重く見るようになった |
| 自分のライフ | 100 | **75.6** | 自分のライフは思ったほど守らなくてよい |
| 自分の場のコア | 3 | **1.5** | コアを盤面に貯めることの価値は低い |
| 自分の回復スピリット数 | 6 | **8.0** | ブロッカーは思ったより大事 |
| マジックを撃つ値打ち | 60 | **46.8** | 先読みで実測するので、下駄は小さくてよい |

**手で置いた値は、だいたい方向は合っていたが大きさがずれていた。**
とくに「打点をもっと重く見るべき」は、人の目では気づけなかったところ。

## 気をつけること

### 「鍛えた」と「強くなった」は別物

学習の最後に、**学習に使っていない種で1000試合**測り直して、
その数字を `学習した重み.ts` のコメントに書き込んでいる。
ここが50%を大きく超えていなければ、その学習結果は採用しないこと。

### 重みに項目を足したら、学習を回し直す

`評価の重み` に項目を足しても `学習した重み.ts` は古いままなので、
**その項目だけ既定値に落ちる**。気づけないので、
「焼き込んだ重みは、いまの評価の重みと同じ項目を持つ」テストで止めている。

### 交代の閾値はばらつきとの兼ね合い

300試合の勝率のばらつきは標準誤差で約2.9%。閾値を50%ちょうどにすると、
**ばらつきだけで王者が入れ替わり続ける**。いまは54%（約1.4σ）にしてある。
それでも紛れは残るので、最後の確かめ（学習に使っていない種）が本当の判定になる。

## 残っていること（段5）

- **手元での微調整** … 対戦の結果をセーブデータに貯め、重みを少しずつ動かす
- **レート戦** … レート1500を基準に正規分布で振り、そこから `強さ`（0〜1）を作る。
  `強さ` は既に1本通してあるので、対応表を1つ書けば繋がる

また、**考える時間がまだ大きく余っている**（中央値2ms 対 許された1〜3秒）。
相手の返しまで読む・手の順番を組み合わせて読む、といった深さを足す余地がある。

# 段4.5：実際に対戦して見つけた穴

腕試しの数字（練習用AIに87.3%）は良かったが、**1試合を1手ずつ見たら明らかにおかしかった。**
数字だけ見ていては見つからなかったので、実戦で確かめるのは要る。

## 見つけたこと

### 1. ほとんどLvアップしない（245ターンで9回）

場のスピリットの**96.3%がLv1のまま**だった。

原因は重みの桁。BPは1点あたり0.000828なので、Lv2で+2000BPしても**1.66点**。
一方コア2個は**6.8点**。**上げるほど損**という計算になっていた。

実戦では「BPが上なら相打ちにならずに勝てる」段差の価値が大きいので、明確な見誤り。

### 2. 起動効果を1度も撃たない（40試合で0回）——**測り方のほうが壊れていた**

しかも「選ばれない」のではなく、**選択肢に一度も挙がっていなかった**。

調べると、自己対戦の進行役（`対戦進行.ts`）が
**割り込みの窓を一度も開いていなかった**。
風牙の起動効果は両方とも【起動：フラッシュ】なので、撃つ機会が構造的に無かった。

**AIが撃たないのではなく、撃てる場面を作っていなかった。**
そして学習は自己対戦で回すので、**フラッシュの使い方を一切学べていなかった**。
測り方の穴が、そのまま強さの穴になっていた。

## 直したこと

| 直し | 中身 |
|---|---|
| 割り込みの窓を開く | `対戦進行.ts` がアタック後（8-1-2）とブロック後（8-1-4）に窓を回す |
| BPの段差を評価に入れる | 「相手の最大BPを上回る自分のスピリット数」を重みに追加 |
| 余ったコアをLvアップに回す | 重みに任せず**規則**として置く（利用者の指定） |

### 「余ったコア」の切り方は、測って決めた

利用者の指定は「**確実に召喚に使えない**余るコアは利用する」。
どこからが「確実に使えない」かで2通り試した。

| 切り方 | Lvアップ回数 | 規則なしに対する勝率 |
|---|---|---|
| いちばん**安い**札のぶんだけ残す | 0.17回/ターン | **48.6%**（ものさし50.9%＝約2ポイント負け） |
| いちばん**高い**札のぶんを残す | 0.11回/ターン | **50.7%**（ものさし50.8%＝損なし） |

安いほうに合わせると、**次のターンに出したい重いカードのコアまで乗せてしまう**。
高いほうに合わせれば手札のどれも次に出せるので、そこを超えた分だけが
「確実に召喚に使えない」——指定の言葉にも近い。**高いほうを採った。**

## 直した結果

### AIが打つ手の内訳（40試合・245ターン）

| 手 | 直す前 | 直したあと |
|---|---|---|
| 召喚 | 1.00回/ターン | 0.98回/ターン |
| **起動効果** | **0回** | **0.20回/ターン** |
| **Lvアップ** | 0.04回/ターン | **0.11回/ターン** |
| マジック使用 | 0.04回/ターン | 0.05回/ターン |
| ネクサス配置 | 0.06回/ターン | 0.05回/ターン |

Lv2でいる割合は 3.7% → **7.5%**。

### 実戦の見え方

直す前は、こちらのBP5000に毎回BP5000をぶつけて相打ちにするだけだった。
いまはLv2（BP8000）に上げてから受けるので、**一方的に取って生き残る**。

```
AI  グン＝ガタ を Lv2 へ
AI  ブロック：グン＝ガタ(BP8000) で グン＝ガタ(BP5000) を受ける
```

### 勝率

| | |
|---|---|
| 対 練習用AI | **85.7%** |
| 鍛えた重み 対 手で置いた重み | **59.2%** |
| ものさし（同じAIどうし） | 51.7% |

**勝率そのものは前とほぼ変わらない**（87.3% → 85.7%、ものさしの幅の中）。
練習用AIも同じ穴（起動効果を使えない）を持っているので、
この直しは相手に対して差が出にくい。**変わったのは打ち回しの中身のほう。**

1手の応答は中央値2ms・最大10msで、前と変わらない。

## ここから学んだこと

**物差しが弱いと、穴はそのまま残る。** 練習用AIはLvアップこそするが、
マジックも起動効果も使えない。そこに87%勝てても、
「起動効果を1度も撃たない」ことは数字に出てこなかった。

**自己対戦の進行役が、本番と同じ場面を作れているかを疑うこと。**
割り込みの窓が開いていなければ、フラッシュのカードは
測定からも学習からも丸ごと抜け落ちる。

# 段4.6：物差しを固定する／深く読んでみる

前の段で分かったのは「**物差しが弱いと穴はそのまま残る**」ということだった。
練習用AIに87%勝っていても、起動効果を1度も撃たないことは数字に出てこなかった。

## 歴代の物差しを凍らせて置く

`AI/物差しの重み.ts`。**そのとき一番強かったAIの重み**を凍らせたもの。

テスト「いまのAIは、歴代の物差しに負け越さない」が見張る。
弱くなったらここで落ちる。練習用AIと違い、物差し自身が
起動効果もマジックもLvアップも使うので、そこの穴が写る。

**手で書き換えないこと。** 新しい重みが物差しに勝ったと確かめられたときだけ、
`学習した重み.ts` の中身をここへ写して更新する。

## 相手の返しまで読む（深さ2）→ **2度しくじってから効いた**

待たされる時間が中央値2msと大きく余っていたので、
「自分の1手を打ったあと、**相手のターンを1つ通してから**評価する」を試した。

| 種の範囲 | ものさし（深1 対 深1） | 深2 対 深1 | かかった時間 |
|---|---|---|---|
| 660001〜 | 51.0% | **48.3%** | 3.5倍 |
| 770001〜 | 51.2% | **50.0%** | 3.5倍 |

ここで一度「効かない」と結論しかけた。だが利用者から
**「相手を読むのは、思考をする高度なAIどうしの対戦でこそ意味があるのでは」**
と指摘を受けて測り直したところ、原因は2つあった。

### しくじり1：読みの中の相手が弱すぎた

通すあいだ双方を「先読みしない安い相手」で動かしていた。
つまり読んでいたのは**弱い相手の返し**で、出来上がった盤面は
試した手の良し悪しより安い相手の打ち回しに引きずられていた。

読みの中の相手を「深さ1の先読みをする相手」に変えたら、
48.5% → 51.0% まで戻った（ものさしは 51.0%）。まだ足りない。

### しくじり2：何回読んでも同じ盤面だった

「1回の読みで勝負がつくと勝敗の点（±100万）が結論を飲み込む」と考え、
何回か読んで平均する仕掛けを入れた。ところが

| | 種660001〜 | 種770001〜 |
|---|---|---|
| 深2×1回 | 51.0% | 47.5% |
| 深2×5回 | 51.0% | 47.5% |

**小数点まで同じ数字**になった。読みの中の相手が最善手だけを指すので、
何回読んでも**まったく同じ盤面**にたどり着いていた。
平均する仕掛けが何も働いていなかった（また「働いていない守り」を作りかけた）。

読みの中の相手を少し散らして（強さ0.8）から測り直すと、効くようになった。

### 直したあと（400試合ずつ・3つの種の範囲）

| 種の範囲 | ものさし（深1 対 深1） | **3回読む** | 7回読む |
|---|---|---|---|
| 660001〜 | 51.0% | **53.0%** | 51.5% |
| 770001〜 | 51.2% | **52.8%** | 51.7% |
| 880001〜 | 51.0% | **55.0%** | 53.3% |

**+2.5ポイント。** 7回に増やしても良くならなかったので、既定は3回。
`読む深さ` の既定を **2** にした。

### 待たされる時間

| 中央値 | 95%点 | 最大 |
|---|---|---|
| **2ms** | 29ms | 61ms |

許された1〜3秒に対してまだ十分に余っている。

### 学習の中では深さ1のまま

深さ2は1手あたり30倍ほど重く、40世代回すと何時間もかかる。
鍛えているのは重みであって読みの深さではないので、
学習の中は浅く速く回して、同じ時間で多く試すほうを採った。

### ここから学んだこと

**「効かなかった」で止めると、原因を1つも潰さないまま終わる。**
今回は2つとも測り方の側の欠陥で、直したら素直に効いた。
効かないときは「そもそも仕掛けが働いているか」を先に疑うこと。

# 段4.7：深く読ませたら受け身になった（既定を深さ1に戻す）

利用者から実機で **「召喚をしなさすぎる」** と指摘を受けた。

## 何が起きていたか

`読む深さ2` を既定にしたのが原因だった。
打った手のあと相手に1ターン与えて評価するので、
「出した先から壊される」見込みが常に乗り、**出し渋るようになっていた**。

| | 召喚/ターン |
|---|---|
| 深さ1 | 0.94 |
| 深さ2 | **0.76** |

## わたしの見落とし：物差しが1つしかなかった

深さ2は深さ1と戦わせると 53.0%／54.8%／54.0% で勝ち越す。
それを見て「深く読むほうが強い」と結論した。

**相手を替えたら逆だった。**

| 400試合×3つの種の範囲 | 対 練習用AI | 深2 対 深1 |
|---|---|---|
| 深さ1 | 87.5 / 86.8 / 90.3% | — |
| 深さ2 | **80.0 / 81.0 / 80.0%** | 53.0 / 54.8 / 54.0% |

深さ2は**同じ受け身どうしなら勝つが、攻めてくる相手には8ポイント負ける**。
人が相手のときは攻めてくる側なので、深さ1のほうが噛み合う。

**既定を深さ1に戻した。** `読む深さ` は設定として残してある。

## あわせて直した「余るコア」の線引き

Lv上げの規則も、線引きを動かすたびに別のところが壊れていた。3度目の直し。

| 線引き | 召喚/ターン | Lv上げ/ターン | 規則なしに対する勝率（500試合×3） |
|---|---|---|---|
| 規則なし | 0.97 | 0.14 | 50.4 / 51.6 / 48.8% |
| いちばん安い札ぶん残す | — | — | 約2ポイント負け |
| 払えない札まで数える | 0.97 | 0.11 | — （Lv上げが起きない） |
| いま払える札だけ（余裕0） | 0.91 | 0.17 | **48.8 / 48.2 / 47.0%** |
| **あと2個で届く札まで（余裕2）** | **0.96** | 0.15 | **50.4 / 51.0 / 48.8%** |

次のターンにはコアが1個増えるので、**あと2個で届く札までは「使う見込みがある」**とみなす。
そこを超えた分だけが「確実に召喚に使えない」コアで、Lv上げに回してよい。

## 直したあと

| | |
|---|---|
| 召喚 | **0.97回/ターン** |
| Lvアップ | 0.11回/ターン（規則を入れる前は0.04） |
| 起動効果 | 0.18回/ターン |
| 対 練習用AI | **87.5〜90.3%** |
| 1手の応答 | 中央値2ms・最大8ms |

## ここから学んだこと

**物差しは必ず2種類以上で見ること。**
1つの相手に勝ち越しただけで既定を変えると、
別の相手には負ける戦い方に寄っていても気づけない。

そして今回も、**気づいたのは数字ではなく実機の対戦**だった。
