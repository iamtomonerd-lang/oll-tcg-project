# AIを強くする

「学習し、より高度な対戦ができるようにしたい」（利用者）に対する作り。

決めたこと（利用者の判断）：

| 決めごと | 選んだもの |
|---|---|
| 学習の形 | **両方** ＝ オフラインで鍛えて焼き込み＋手元で微調整 |
| 1手に待てる時間 | **1〜3秒**（先読みまで踏み込む） |
| 強さの見え方 | まずは最強のものだけ。**あとでレート戦**（1500を基準に正規分布） |

段階に分けて出す。**この文書は段3が終わった時点のもの。**

| 段 | 中身 | 状態 |
|---|---|---|
| 1 | 手を広げる＋評価関数で選ぶ＋強さのつまみ | **済** |
| 2 | 盤面の複製（先読みの土台） | **済** |
| 3 | 先読み（打ってみて測る） | **済**（1手先。まだ深く読む余地が大きい） |
| 4 | 学習（自己対戦で重みを鍛えて焼き込む） | これから |
| 5 | 手元での微調整＋レート戦 | これから |

---

## 段1でやったこと

### まず「手が届く範囲」を広げた

いちばん効いたのはここ。賢さ以前に、**AIは手札の半分を使えていなかった**。

| これまでの練習用AI | いまの思考AI |
|---|---|
| スピリットの召喚だけ | 召喚・**ネクサスの配置**・**マジックの使用** |
| — | **起動効果** |
| 割り込みでは常にパス | **［フラッシュ］のマジック・起動効果を撃つ** |
| — | 《ソウルマジック》での支払い |
| リザーブからのLvアップ | 同じ |

`AI/打てる手.ts` が「いま何ができるか」を全部並べる。
挙げる側（打てる手）と選ぶ側（思考AI）を分けてあるので、
**選び方だけを学習で差し替えられる。**

### 盤面を1つの数字にした

`AI/盤面評価.ts`。ライフ・シンボル数・BP・手札・コアの置き場所などに重みを掛けて足す。

**強さの正体はこの重み。** 思考AIの側には強さを持たせていない。
学習とはこの重みを自己対戦で調整することで、反映先が2か所に散らないようにしてある。

重みは `評価の重み` として外から差し替えられる。

### 強さのつまみを1本入れた

`強さ`（0〜1）＝**最善手を選ぶ確率**。レート戦を入れるとき、
レートからこの数値を作れば強さが連続的に動く。

はじめは「上から何番目までを候補にするか」で弱くしていたが、
手が数個しかない場面では 強さ0.6 でも上位2手に絞られ、最強とほとんど差が出なかった
（実測 77% → 75.5%）。確率にしたら素直に効くようになった。

---

## 測ったこと

`AI/腕試し.ts`。AI同士を何百試合も戦わせて勝率を出す。
**先攻・後攻を入れ替えて半分ずつ**戦わせる（入れ替えないと「強さ」ではなく「先攻」を測る）。
種を渡すので何度回しても同じ結果になる。

### 土俵が傾いていないこと

| 組み合わせ | 先の勝率 |
|---|---|
| 練習用AI 対 練習用AI | 49.0% |
| 思考AI 対 思考AI | 54.0% |

同じもの同士で五分。ここが崩れていたら、下の数字は強さではなく測り方を見ている。

### 強くなったか（200試合・先後入れ替え）

| 種 | 思考AI の勝率 |
|---|---|
| 1〜200 | **74.5%** |
| 501〜700 | **74.5%** |

### 強さのつまみ（300試合、対 練習用AI）

| 強さ | 勝率 |
|---|---|
| 1（最強） | 75.0% |
| 0.8 | 74.7% |
| 0.6 | 63.3% |
| 0.4 | 52.3% |
| 0.2 | 54.3% |
| 0 | 38.3% |

0.2 と 0.4 の逆転は誤差の範囲。両端はしっかり離れている。

### 実際の対戦の道（ゲームAPI）でも使っているか

自己対戦だけで測ると、画面に繋がっていなくても数字は出てしまう。
`/api/` を通した対戦でも数える。

| | 結果 |
|---|---|
| 12試合でAIがマジックを使った回数 | **56回**（直す前は 0回） |
| 割り込みの窓でAIに判断を尋ねた回数 | **90回**（直す前は尋ねてすらいなかった） |

画面（820×1180、起動直後から利用者が押せるものだけを辿る）。種 11/3/7/77/5：

- 5種すべてで**決着まで進む**（進行が詰まらない）
- AIは1試合あたり**5〜7枚のマジックを使う**
- 画面のエラーは0件

## 途中で分かったこと

### AIがマジックを一度も撃たなかった

手を挙げられるようにしただけでは撃たなかった。
見込みの計算が「手札が1枚減る・コアが減る」の引き算だけになっていて、
**撃つ手がいつも損に見えていた**（フレイムハリケーンで −10点）。

効果の値打ちを重みとして立てた（`マジックを撃つ値打ち` `召喚時効果が当たる値打ち`）。
これで撃つようになった。中身までは読んでいないので、
段2で盤面を複製できるようになったら実測に置き換える。

### ［フラッシュ］のマジックは取っておくべきか → 測ったら「変わらない」

「相手のアタックに合わせて撃つほうが得では」と考えて、
メインで撃つときの割引を入れて500試合ずつ測った。

| 割引 | 素の思考AIに対する勝率 |
|---|---|
| 0（割り引かない） | 51.8% |
| 20 | 49.0% |
| 40 | 49.4% |
| 60 | 49.4% |
| 80 | 49.4% |

**得にならなかった。** 重みは残したまま既定を0にしてある（学習で見直せる）。
思い込みで手を入れず、測ってから決めること。

## 段2以降でやること

### 段2：盤面の複製

いまは**打った手を戻せない**ので、手の良し悪しを「見込み」で足し引きしている。
効果が何をするかは読めていない。

複製できるようになれば「打ってみて測る」に置き換わり、
見込みのズレがまるごと消える。1〜3秒の先読みもここが土台になる。

データ層は小さい（`カード`・`ゾーン`・`プレイヤー` はどれも
`状態: Map` と `数値: Map` を持つ `ゲーム物`、合わせて472行）。
面倒なのは **管理クラスがカードの参照を持っている**ところで、
複製するときに参照先を張り替える必要がある。

| 参照を持つもの | 中身 |
|---|---|
| 一時効果管理 | BP変更記録 |
| 常在効果管理 | 登録済み制約 |
| 誘発型効果管理 | 誘発予約のキュー |
| 効果実行器 | 選択待ちの対象候補 |

### 段4：学習

自己対戦は **1試合1.76ms**（200試合で352ms）。
数万〜数十万試合を回して重みを鍛えるのは十分に現実的。

鍛えた重みは `学習した重み.ts` に書き出してビルドに含める。
ブラウザ側はサーバー無しのまま、開いた瞬間から鍛えた強さになる。

### 段5：レート戦

`強さ`（0〜1）が既に1本通してある。レート1500を基準に正規分布で振り、
そこから 強さ を作れば、そのまま繋がる。

## 引っかかったところ（同じ轍を踏まないために）

### 画面の確認で「ボタンの hidden」を見てはいけない

パネルが閉じていても、**中のボタンの `hidden` は false のまま**。
大きさが 0×0 になるだけ。

これで2回はまった。1回目は「ブロックしない」を800回押し続けて対戦が進まず、
2回目は閉じたはずの効果パネルのボタンを755回押していた。
どちらも**アプリは正しく、確かめ方が間違っていた**。

`position: fixed` で `offsetParent` が使えないのと同じ話で、
**見えているかは `getBoundingClientRect()` の幅・高さで見る。**
親のパネルの `hidden` も一緒に見ること。

### 種を1つに決め打ちしたテストは、AIを変えると落ちる

「［フラッシュ］のマジックをメインステップで撃つ」テストが、
AIを強くしたら落ちた。種11でその場面に入れなくなったため。

確かめたいのは「**その場面が来たら撃てること**」なので、
場面が現れるまで種を変えて探す形に直した。
AIの気分で落ちるテストは、直しても意味が伝わらない。

# 段2・段3：盤面を複製して、打ってみて測る

## 何が変わったか

段1のAIは「その手を打ったらどうなるか」を**見込みで足し引き**していた。
盤面を複製できなかったので、打った手を戻せなかったため。
効果が何をするかは読めず、下駄（重み）で表すしかなかった。

いまは **複製の上で実際に打って、出来上がった盤面を評価する**。
効果の結果まで盤面に出るので、下駄がいらない。

```
段1  この手を打つと 手札-1・コア-4 …… だいたい -45点くらいか
段3  複製して打ってみたら 相手のスピリットが1体消えた …… +31点
```

## 複製の作り

`試合.複製する(種)`。データ層と、状態を持つ管理を全部写す。

| 写すもの | 中身 |
|---|---|
| ゲームエンジン | プレイヤー・ゾーン・カード（**コアはゾーンとカードの中にある**ので一緒に付いてくる） |
| 一時効果管理 | 期限付きのBP補正 |
| 常在効果管理 | 期限付きの制約（「ブロックされない」など） |
| ターン履歴管理 | 『このターンにライフが減っていたなら』 |
| 誘発型効果管理 | 誘発の待ち行列 |
| 置換型効果管理 | 置換済みの事象 |
| 制限効果管理 | 〔ターン1回〕をもう使ったか |
| 効果実行器 | 片付け待ちのマジック・事象連番 |

カードを指している記録は、**複製したカードに差し替える**。
ここを怠ると、複製の中の記録が本物のカードを指したままになり、
複製をいじったつもりが本物に漏れる。

**効果の答え待ちの最中は複製を断る**（例外を投げる）。
途中で複製すると「誰に何を聞いていたか」を取り違えるため。
AIが手を選ぶのは常に答え待ちでない場面なので、これで足りる。

速さは **1回 0.054〜0.070ms**（毎秒 約15,000〜18,000回）。

## 測ったこと

### 複製が本物と同じか

`盤面の指紋` で盤面を1本の文字列にして比べる。

1. 複製した直後は本物と寸分たがわない
2. 複製に手を打っても本物は動かない
3. 本物と複製に同じ手を打てば、同じ盤面になる

### 強くなったか（300試合・先後入れ替え）

| | 練習用AI に対する勝率 |
|---|---|
| 見込みで選ぶ（段1） | 79.7% |
| **複製して打ってみる（段3）** | **84.3%** |

直接対決（先読み 対 見込み）… **57.7%**

### 利用者が待たされる時間

`/api/` を通した373手の実測。

| 中央値 | 95%点 | 最大 |
|---|---|---|
| **2ms** | 4ms | 17ms |

**許された1〜3秒に対して桁違いに余っている。**
いまは「自分の1手だけ」を読んでいるので、相手の返しまで読む・
手の順番を組み合わせて読む、といった深さを足す余地が大きい。

## 段2・段3で見つけた不具合

### テストが「空っぽ」を見ていた（複製の確認が素通りだった）

複製のテストを書いて通ったあと、念のため
**写しの呼び出しを1行ずつ消して、テストが落ちるか**を確かめた。

結果、**7つ全部を消してもテストは通った。**

途中まで進めただけの盤面では、どの管理も中身が空だったため。
空のものを写しても写さなくても同じで、あれは
「複製できている」ではなく「何も入っていない」を見ていた。

いまは中身を入れてから複製し、届いたかを1つずつ見ている。
7つのうちどれを消してもテストが落ちる。

**「テストが通った」と「テストが働いている」は別物。**
新しく守りを入れたら、**守りを外して落ちること**まで確かめる。

### コアの代金を二重に取っていた

先読みを入れたら、AIが**マジックを1枚も撃たなくなった**（40回 → 0回）。

調べると、複製の上では正しく相手を壊せていた。原因は評価の重みで、
`自分のトラッシュのコア: -2` が**同じ代金を二重に取っていた**。

```
コアを1個払う → リザーブから減る（-4）→ さらにトラッシュで罰（-2）＝ 1個6の値段
```

そのせいでコストの重い手が軒並み損に見えていた。
払った痛みは「リザーブから消えたこと」で既に表せている。

0 に直して、800試合×3つの種の範囲で測った。

| 種の範囲 | 同じ重み（ものさし） | トラッシュの罰なし |
|---|---|---|
| 1〜 | 51.7% | **58.6%** |
| 2001〜 | 50.2% | **56.5%** |
| 5001〜 | 47.3% | **54.6%** |

どの範囲でも約7ポイント上がった。練習用AIに対する勝率も 77.0% → **84.3%**。

**同じ重みどうしを「ものさし」として一緒に測ること。**
最初に測ったとき、ものさしを取らずに 53.2% を見て
「差がある」と読みかけた。ものさしを取ったら 50% 前後で、
53.2% はただのばらつきだった。

### 破壊は2段階（複製でも同じ）

複製の上で手を打ったあと、`効果実行器.キューを進める()` と
`ルール処理を実行する()` を呼ばないと、壊した相手が**待機状態のまま場に残る**。
評価がそれを生きていると数えるので、除去の手が全部損に見える。

盤面評価の側でも、**待機状態のカードは数えない**ようにした。
どちらか一方だけだと、また同じ形で間違える。
